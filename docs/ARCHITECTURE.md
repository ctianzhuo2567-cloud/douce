# 架构边界

## 当前数据流

```text
系统文件选择器
    ↓
持久化图片读取权限
    ↓
图纸元数据仓库
    ↓
图纸库 / 详情预览 / 识别队列
```

App 只保存用户选择的图片 URI 和图纸元数据，不覆盖原始图片。详情页镜像目前是非破坏性的预览变换。

框选区域使用 `0..1` 的归一化坐标保存，而不是保存屏幕像素。这样同一张图片在不同手机尺寸和缩放比例下仍指向同一片原图区域。

## OCR 预留链路

```text
原图
    ↓
用户框选色号说明区域
    ↓
高分辨率裁切与预处理
    ↓
设备端 OCR
    ↓
MardCode.normalize()
    ↓
置信度审核
    ↓
已确认色号与数量
```

`MardRecognitionService` 是 OCR 实现边界。任何识别器都必须输出原始文本、置信度和警告，不能把低置信度结果静默标记为已确认。

## MARD 目录

第一阶段固定使用 MARD 221 做库存身份和字符校验，不做颜色匹配。

- MARD 221：A、B、C、D、E、F、G、H、M 系列，共 221 色

豆库把“未录入”和“明确为 0（缺货）”分开保存，避免刚启用 App 时把全部 221 色误报为缺货。

屏幕 HEX 来自公开核对数据，仅用于界面色块；不同公开来源有色差，实物对色必须以用户手中的实体 MARD 221 色卡为准。

色号标准化示例：`A01 → A1`、`B-07 → B7`、`ZG 08 → ZG8`。

## 镜像边界

当前框架对整张图片做左右或上下预览镜像。后续加入主体区域裁剪后，正式镜像导出只翻转图纸主体，说明文字保持正向。
